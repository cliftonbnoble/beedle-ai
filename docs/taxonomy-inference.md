# Truthful taxonomy suggestions (M23)

The checked-in case types describe zoning, licensing and benefits templates; they have not been reconciled with the rent-board corpus. Automatic inference therefore returns the configured **General** fallback with score 0, `fallback: true` and an explicit unreviewed-policy reason. Explicit human template selection remains available with a warning. No rent-board categories, calibration results or domain approval were invented.

## Evidence and abstention

Inference version `taxonomy-evidence-2` uses bounded, deterministic evidence. A substantive suggestion requires a reviewed policy covering the document's jurisdiction, a score at least the configured minimum (default 0.55), and a sufficient margin (default 0.15). These are conservative **heuristic guardrails**, not measured probabilities or calibrated production thresholds. Scores are labeled `uncalibrated_evidence_score`; the reviewer display no longer renders them as percentage confidence. Raising the thresholds remains possible; lowering them below the guardrails is rejected.

Matching uses whole normalized token phrases, deduplicated aliases and exact normalized structured references. Repeated words/aliases do not increase scores. A multiword type phrase or exact mapped index can supply a primary signal; single broad words, rule/ordinance hints alone and template focus questions do not establish a type. Title/body signals and exact hints have fixed versioned weights. Ties, insufficient margins, conflicting mapped indexes, negated structured conflicts and weak/absent evidence abstain. Negation handling is deliberately conservative, sentence-scoped lexical exclusion; it is not a legal or natural-language entailment model. A denial of relief following a type phrase still indicates a proceeding of that type.

Text above 240,000 characters or more than 200 references in any category causes abstention, rather than selecting from silently truncated evidence. Configuration bounds case counts and aliases; duplicate IDs, ambiguous aliases, missing defaults and reviewed policies without declared reviewer/date/jurisdiction/evaluation evidence are rejected. Array order cannot decide a tie or a no-signal case. The fallback must be an explicit General/Unknown type, with a safe Unknown result for invalid internal configuration.

## Existing suggestions and reviewer state

Old suggestions remain in the original `metadata_json`; the repair does not reprocess sources, change legal reference provenance, revoke approvals or rewrite history. The current reader treats old/unknown/corrupt/unreviewed policy output as General/Unknown, with a bounded prior suggestion for comparison. A retained substantive suggestion must match the current inference/config version and a reviewed policy with a valid score/type. A configured label is used, rather than an arbitrary stored label. Missing, nonnumeric and nonfinite confidence is unknown, not evidence of high quality.

The queue and detail reader use the same policy. Queue projection retains only required version/status fields and bounded prior labels, without loading unused parser payloads. Reviewer policy `reviewer-queue-2/taxonomy-evidence-2/reviewer-policy-1` and the M20 contract were updated. Existing materialization fails readiness until the bounded reviewer builder rebuilds it. Low/unknown taxonomy is a review caution; existing human approval eligibility remains unchanged. Filter regression fixtures now traverse all cursor pages because more unknown rows can correctly enter the queue.

## Domain review and rollout

Before enabling substantive inference, domain reviewers must reconcile case types, aliases and exact reference mappings with the actual forum and jurisdiction. Evaluate an independently labeled representative corpus covering every supported type, absent signal, ties, negation, conflicting references and unfamiliar cases. Measure type precision, coverage/abstention and error costs separately; use M19's independent-evaluation practices. Select and justify thresholds from held-out evidence, retain prior suggestions for comparison, and review any template or queue changes. Synthetic tests prove deterministic behavior, not classification quality.

Record a new config version, declared reviewer/time, explicit jurisdiction list and private evaluation reference before changing `review_status` to `reviewed_for_inference`. These declarations are configuration provenance, not authenticated reviewer identity or automatic verification of an evaluation artifact. H01 remains separate. Missing/out-of-scope document jurisdiction must abstain. Rebuild reviewer materialization after any inference/config change; do not just flip a ready marker.

M23 itself adds no schema migration; follow the current M20 contract, including M25's schema 33 and date-filter synchronization requirements. Rehearse queue rebuild and actual reviewer/browser flows in isolated preview before M20 release. Counts, effort ordering and suggestions can change substantially as legacy false certainty becomes unknown. Keep the safe fallback and prior labels during a forward repair. An old release requires its matching queue policy rebuild and cannot be used to bypass M22 source-lineage publication semantics. Production taxonomy acceptance and rollout remain external gates; no deployment or production data was used here.
