## Compatibility and remaining limits

The PDF body-text check intentionally holds pages with fewer than 20 body letters/digits outside margin bands. It can hold legitimate very short pages for manual review. It does not establish complete OCR coverage or legal/reading-order accuracy; continue comparing representative legal originals before rollout.

Catalogs built by the earlier normalizer may already contain text merged across distinct Parts. Rebuild those catalogs from the retained original import artifacts; changing lookup code cannot separate previously merged bodies. Retained rows with intact Part metadata are read using that identity even if historical normalized columns lost the qualifier. Bare citations spanning multiple Parts now remain unresolved until the Part is explicitly reviewed. Revalidate and reapprove affected document metadata through the documented catalog workflow.

These migrations and commits have not been deployed. Existing local rehearsal databases that already applied an earlier migration definition must be recreated or deliberately reconciled before retesting; editing a migration file does not update an already-applied database. Production schema/data backups, isolated migration/corpus rehearsal, preview provisioning, actual provider testing and the existing release gates still apply.

The full dependency registry audit remains unrun under the existing approval-review restriction on transmitting package inventory. Authentication, broader cross-reviewer mutation semantics, general maintenance/search optimization and the adapter migration remain deferred under the user's scope.
