# Reviewer CSV text policy (M24)

Queue exports, adjudication templates and local reviewer worksheets use the same `spreadsheet-text-1` serializer. Untrusted text beginning with `=`, `+`, `-` or `@` receives a visible **`[text] `** prefix inside a quoted field. Detection looks past leading Unicode whitespace, formatting characters and C0/C1 controls, and includes full-width variants. Leading control/format characters also receive protection. Actual finite numeric values, including negative numbers, remain numeric; strings such as `-42` are protected text. Normal fields are preserved, and quotes, comma/semicolon, tabs and CR/LF receive CSV boundary quoting.

This is an intentional presentation change. For example, a source title `=1+1` displays as `[text] =1+1`. A visible prefix is not spreadsheet escape syntax and remains ordinary text after CSV save/reopen. We chose it because hidden quote/escape handling varies across spreadsheet clients and transformations. [OWASP's CSV guidance](https://github.com/OWASP/www-community/blob/master/pages/attacks/CSV_Injection.md) explains the Excel save/reopen limitation and the lack of a universal CSV sanitizer. The prefix and quoting are implemented/tested here; actual supported Excel/LibreOffice versions and locale-specific import/save/reopen behavior still require an isolated client acceptance check. Use the comma-separated import setting. No spreadsheet formulas or external payloads were executed during verification.

JSON exports retain the original title, citation, notes and typed numbers. Both the JSON packet and CSV HTTP header identify the policy; adjudication JSON rows are also unchanged. **Use JSON for exact machine round trips.** Never heuristically remove `[text] `, a tab or an apostrophe from imported text: an original value can legitimately contain those characters. Prefixes remain literal through the CSV readers and later export. Removing the prefix by hand removes that cell's presentation protection. Approval/mutation clients must continue validating document identity, revision and the actual replacement reference rather than treating an edited CSV title as identity.

The existing adjudication/worksheet readers now parse logical CSV records, preserving quoted multiline cells, CR/LF, escaped quotes and physical source line numbers. They reject malformed quoting, duplicate headers and mismatched field counts rather than silently shifting values into another column. Parsing is bounded to 32 million input string units, 1,048,576 string units per field, 200 columns and 100,001 records. File-loading tools still read the private local file before parsing; these are parser bounds, not a streaming filesystem quota. No parser automatically decodes presentation protection into executable text. JSON loaders preserve raw values.

Rollout needs no schema migration or source rewrite. Existing raw JSON/CSV files are not modified. Re-export prior reviewer packets to obtain the protection; earlier downloaded CSVs retain their old behavior. Import scripts sending permissive malformed CSV may now fail and should produce valid quoted records or use JSON. The safe prefix is deliberately visible and can affect downstream string comparisons. Prefer a forward serializer repair if a client incompatibility is found; keep protected CSV and lossless JSON separate. Authentication, authorization, legal adjudication and other export formats remain outside this finding.
